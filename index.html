    SNSF Research Project — Bank Regulation and Corporate Financing Decisions

    Research project · UZH / ZHAW · SNSF-funded research agenda
    2024–Present

    This SNSF-funded research project investigates how post-crisis banking regulation affects firms, banks, and credit markets. My work focuses on the corporate finance part of the project: whether Basel III finalization and the regulatory treatment of large corporate exposures influence firms' financing choices around a EUR 500 million revenue threshold.

    The project combines institutional knowledge of banking regulation, empirical corporate finance, large-scale financial data construction, and quasi-experimental research design. It studies whether firms close to the regulatory threshold adjust their reliance on bank debt, bond debt, secured borrowing, short-term debt, debt maturity, and overall leverage.

    Conceptual Overview
    01 Regulatory setting
    Basel III finalization
    Regulatory change affecting the treatment of certain large corporate exposures.
    EUR 500M revenue threshold
    Threshold used to compare firms close to the regulatory cutoff.

    Compustat
    Accounting and financial statement data.
    Capital IQ
    Debt structure and corporate financing data.

    ↓
    03 Data integration, cleaning & screening
    Merging & identifiers
    Cross-source linking, identifier matching, and firm-level panel construction.
    Cleaning & standardisation
    Missing values, units, currencies, fiscal years, formats, and inconsistent records.
    Screening rules
    Coverage filters, sample restrictions, outlier treatment, and consistency checks.
    ↓
    04 Variable construction
    Debt structure variables
    Bank debt, bond debt, secured debt, short-term debt, debt maturity, and total debt.

    Leverage, firm size, threshold assignment, interest coverage, and related firm-level measures.

    • A central part of the work involved data cleaning, identifier matching, dataset merging, screening rules, missing-value handling, outlier treatment, and consistency checks.

    CERN - CMS Software Validation: Automated Testing Pipeline

    CERN Summer Student · Software Developer
    2022

    During the CERN Summer Student Programme, I designed and implemented a Python-based automation workflow for monitoring new CMS software releases and triggering the corresponding validation pipeline. The project started from an open-ended operational problem and required translating the release-validation process into a reliable multi-stage software workflow.

    The system had to handle scheduled execution, delayed dependencies, conditional steps, waiting periods, interruptions, and recovery without restarting the full process from the beginning. The core technical challenge was not only writing code, but designing workflow logic that was robust, maintainable, and suitable for handover in a research software environment.

    01 Operational problem
    New software releases
    CMS software versions had to be monitored regularly and processed when available.
    Manual validation burden
    The existing process required repeated manual checks and multi-step coordination.
    ↓
    02 Workflow design
    Release detection
    Scheduled checks for new software versions and relevant release information.
    Pipeline triggering
    Automated execution of the corresponding validation steps after release detection.
    Dependency logic
    Conditional execution depending on whether required inputs and tests were ready.
    ↓
    03 Robust execution
    Checkpointing
    Saved workflow state so the process could resume after waiting periods or interruptions.
    State persistence
    Preserved information about completed stages, pending steps, and current workflow status.
    Failure recovery
    Continued from the correct stage instead of restarting the full process.
    ↓
    04 Software validation workflow
    Automated validation process
    Reduced manual intervention across a multi-stage release-validation workflow.
    Maintainable handover
    Structured the workflow logic to make the system understandable and maintainable.
    Key takeaways:
    • I designed a Python-based automation workflow from scratch for monitoring CMS software releases and triggering validation steps.
    • The project required decomposing an open-ended operational problem into a structured, multi-stage software workflow.
    • I implemented checkpointing, state persistence, conditional execution, waiting logic, and recovery from interruptions.
    • The system reduced manual intervention and made the validation process more reliable, maintainable, and suitable for handover.
    • The project demonstrates transferable skills in Python automation, workflow design, task orchestration, reliability thinking, debugging, and software maintainability.

    Technical areas: software automation, workflow design, scheduled execution, software validation, task dependencies, checkpointing, state persistence, conditional logic, interruption recovery, and maintainable code design.

    Tools and concepts: Python, automation scripts, scheduled jobs, release monitoring, validation pipelines, checkpoint-based recovery, state management, dependency handling, debugging, documentation, and research software workflows.
